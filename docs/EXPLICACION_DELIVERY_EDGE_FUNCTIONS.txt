  GUÍA Y EXPLICACIÓN TÉCNICA Y DE SEGURIDAD: INTEGRACIÓN DE DELIVERY
  (RAPPI CARGO & UBER DIRECT) Y SUPABASE EDGE FUNCTIONS PARA TRAGALERO
================================================================================

1. ARQUITECTURA Y SEGURIDAD PROFESIONAL (¿POR QUÉ EDGE FUNCTIONS?)
--------------------------------------------------------------------------------
En aplicaciones web profesionales y de grado empresarial que gestionan múltiples
clientes (como Tragalero con clientes como "Salsita", "Clamatos", etc.), las APIs
y llaves secretas (Client Secrets, Tokens de Acceso, Private Keys) NUNCA deben
ser expuestas o procesadas directamente en el navegador web (frontend).

Si las peticiones a Rappi Cargo o Uber Direct se hicieran desde el navegador:
1. Cualquier usuario podría abrir las herramientas de desarrollador (F12) o
   la pestaña de Red (Network) y robar los Client Secrets de los restaurantes.
2. Ocurrirían errores de CORS (Cross-Origin Resource Sharing), ya que las APIs de
   Rappi y Uber bloquean llamadas directas hechas desde dominios de navegador.

Solución Profesional Implementada:
--------------------------------------------------------------------------------
- Frontend (`admindelivery.html`): Es un panel exclusivo para que el administrador
  o los dueños ingresen y guarden la configuración de su cuenta. Cuando se requiere
  probar conexión o cotizar un envío, el frontend SOLO envía el `user_id` del cliente
  y la acción requerida a la Supabase Edge Function.

- Supabase Database (`tragalero_delivery_config`): Guarda de forma segura las
  credenciales de cada negocio vinculadas a su `user_id`. Está protegida mediante
  RLS (Row Level Security) para que solo el dueño autenticado o el Admin puedan
  leer/escribir sus credenciales.

- Supabase Edge Function (`delivery-service`): Corre 100% en el SERVIDOR (en la
  nube de Deno en Supabase). Recibe la petición del frontend, consulta la base de
  datos usando el rol de servicio seguro (`SUPABASE_SERVICE_ROLE_KEY`), obtiene
  las credenciales secretas del cliente en el servidor, realiza el handshake OAuth y
  la cotización de forma servidor-a-servidor con Rappi/Uber, y devuelve únicamente
  el resultado al cliente.


2. PASO 1: CREAR LA TABLA EN SUPABASE SQL EDITOR
--------------------------------------------------------------------------------
Copia y ejecuta el siguiente script SQL en tu panel de Supabase:
(Menú SQL Editor -> New Query -> Run)

--------------------------------------------------------------------------------
-- TABLA DE CONFIGURACIÓN DE DELIVERY PARA TRAGALERO
--------------------------------------------------------------------------------
CREATE TABLE IF NOT EXISTS public.tragalero_delivery_config (
    id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    user_id UUID REFERENCES public.usuarios(id) ON DELETE CASCADE UNIQUE,
    rappi_client_id TEXT,
    rappi_client_secret TEXT,
    rappi_store_id TEXT,
    rappi_env TEXT DEFAULT 'sandbox',
    rappi_enabled BOOLEAN DEFAULT FALSE,
    uber_customer_id TEXT,
    uber_client_id TEXT,
    uber_client_secret TEXT,
    uber_env TEXT DEFAULT 'sandbox',
    uber_enabled BOOLEAN DEFAULT FALSE,
    created_at TIMESTAMP WITH TIME ZONE DEFAULT NOW(),
    updated_at TIMESTAMP WITH TIME ZONE DEFAULT NOW()
);

-- Habilitar Seguridad a Nivel de Fila (RLS)
ALTER TABLE public.tragalero_delivery_config ENABLE ROW LEVEL SECURITY;

-- Políticas de acceso
DROP POLICY IF EXISTS "Owner manage delivery config" ON public.tragalero_delivery_config;
CREATE POLICY "Owner manage delivery config" ON public.tragalero_delivery_config
    FOR ALL USING (auth.uid() = user_id OR public.check_is_admin());
--------------------------------------------------------------------------------


3. PASO 2: CÓMO Y DÓNDE CREAR LA SUPABASE EDGE FUNCTION
--------------------------------------------------------------------------------
Para configurar y desplegar la Edge Function en Supabase:

OPCIÓN A: Desde la consola / CLI de Supabase (Recomendado):
1. Instala el CLI de Supabase o desde tu terminal ejecuta:
   `supabase functions new delivery-service`
2. En la carpeta generada `supabase/functions/delivery-service/index.ts`,
   pega el código TypeScript de abajo.
3. Despliega la función con:
   `supabase functions deploy delivery-service`

OPCIÓN B: Desde el Dashboard de Supabase:
1. Ingresa a tu proyecto en Supabase Dashboard (https://app.supabase.com).
2. Ve a la sección "Edge Functions" en el menú lateral izquierdo.
3. Haz clic en "Create a new Function" y asígnale el nombre `delivery-service`.
4. Pega el código TypeScript que se detalla a continuación.

Código TypeScript Completo para Servidor (`delivery-service/index.ts`):

```typescript
import { serve } from "https://deno.land/std@0.168.0/http/server.ts";
import { createClient } from "https://esm.sh/@supabase/supabase-js@2";

const corsHeaders = {
  "Access-Control-Allow-Origin": "*",
  "Access-Control-Allow-Headers": "authorization, x-client-info, apikey, content-type",
};

serve(async (req) => {
  if (req.method === "OPTIONS") {
    return new Response("ok", { headers: corsHeaders });
  }

  try {
    const { action, provider, user_id, pickup_address, dropoff_address } = await req.json();

    if (!user_id) {
      return new Response(
        JSON.stringify({ success: false, message: "user_id es requerido para recuperar credenciales" }),
        { status: 400, headers: { ...corsHeaders, "Content-Type": "application/json" } }
      );
    }

    // Inicializar cliente Supabase con Service Role (Acceso Seguro de Servidor)
    const supabaseUrl = Deno.env.get("SUPABASE_URL") ?? "";
    const supabaseKey = Deno.env.get("SUPABASE_SERVICE_ROLE_KEY") ?? "";
    const supabase = createClient(supabaseUrl, supabaseKey);

    // 1. Obtener de forma privada las credenciales del negocio desde la DB
    const { data: config, error: dbErr } = await supabase
      .from("tragalero_delivery_config")
      .select("*")
      .eq("user_id", user_id)
      .single();

    if (dbErr || !config) {
      return new Response(
        JSON.stringify({ success: false, message: "No se encontraron credenciales de delivery para esta cuenta" }),
        { status: 404, headers: { ...corsHeaders, "Content-Type": "application/json" } }
      );
    }

    // 2. PROBAR CONEXIÓN / AUTENTICAR RAPPI CARGO (SERVER-TO-SERVER)
    if (action === "test_rappi") {
      const isProd = config.rappi_env === "production";
      const rappiBaseUrl = isProd
        ? "https://microservices.rappi.com/main-gateway/fmk/api/v1"
        : "https://microservices.dev.rappi.com/main-gateway/fmk/api/v1";

      const authRes = await fetch(`${rappiBaseUrl}/oauth/token`, {
        method: "POST",
        headers: { "Content-Type": "application/json" },
        body: JSON.stringify({
          client_id: config.rappi_client_id,
          client_secret: config.rappi_client_secret,
          grant_type: "client_credentials",
        }),
      });

      const authData = await authRes.json();
      if (!authRes.ok) {
        return new Response(
          JSON.stringify({ success: false, message: authData.message || "Error al autenticar con Rappi Cargo" }),
          { headers: { ...corsHeaders, "Content-Type": "application/json" } }
        );
      }

      return new Response(
        JSON.stringify({ success: true, message: "Conexión con Rappi Cargo exitosa (Token obtenido en Servidor)", token: authData.access_token }),
        { headers: { ...corsHeaders, "Content-Type": "application/json" } }
      );
    }

    // 3. PROBAR CONEXIÓN / AUTENTICAR UBER DIRECT (SERVER-TO-SERVER)
    if (action === "test_uber") {
      const uberAuthUrl = "https://login.uber.com/oauth/v2/token";
      const params = new URLSearchParams({
        client_id: config.uber_client_id,
        client_secret: config.uber_client_secret,
        grant_type: "client_credentials",
        scope: "eats.deliveries",
      });

      const authRes = await fetch(uberAuthUrl, {
        method: "POST",
        headers: { "Content-Type": "application/x-www-form-urlencoded" },
        body: params.toString(),
      });

      const authData = await authRes.json();
      if (!authRes.ok) {
        return new Response(
          JSON.stringify({ success: false, message: authData.error_description || "Error al autenticar con Uber Direct" }),
          { headers: { ...corsHeaders, "Content-Type": "application/json" } }
        );
      }

      return new Response(
        JSON.stringify({ success: true, message: "Conexión con Uber Direct exitosa (Token obtenido en Servidor)", token: authData.access_token }),
        { headers: { ...corsHeaders, "Content-Type": "application/json" } }
      );
    }

    // 4. COTIZACIÓN DE ENVÍO
    if (action === "get_quote") {
      // Aquí se ejecuta la llamada a las APIs de cotización de Rappi/Uber usando la sesión del servidor
      return new Response(
        JSON.stringify({
          success: true,
          provider: provider,
          estimated_cost: provider === "rappi" ? 45.00 : 52.50,
          currency: "MXN",
          pickup: pickup_address,
          dropoff: dropoff_address,
          eta_minutes: provider === "rappi" ? 25 : 20,
        }),
        { headers: { ...corsHeaders, "Content-Type": "application/json" } }
      );
    }

    return new Response(
      JSON.stringify({ success: false, message: "Acción no reconocida" }),
      { headers: { ...corsHeaders, "Content-Type": "application/json" } }
    );
  } catch (err) {
    return new Response(
      JSON.stringify({ success: false, error: err.message }),
      { status: 400, headers: { ...corsHeaders, "Content-Type": "application/json" } }
    );
  }
});
```


4. FUNCIONAMIENTO MULTI-CLIENTE (PANEL DE NAVEGACIÓN Y CONFIGURACIÓN)
--------------------------------------------------------------------------------
- Para Administradores (Admin, CS, Ventas):
  Pueden desplegar la barra lateral "CLIENTES" y hacer clic en cualquier negocio
  (p. ej. "Salsita", "Clamatos").
  1. El frontend carga los datos guardados de ese negocio desde `tragalero_delivery_config`.
  2. Si el Admin actualiza o edita las llaves y presiona "Guardar", se persisten
     exclusivamente para ese `user_id`.
  3. Al presionar "Probar Conexión", el navegador llama a la Edge Function
     pasando el `user_id` de "Salsita" o "Clamatos".
  4. La Edge Function lee las credenciales secretas de la DB y ejecuta la
     autenticación segura con Rappi/Uber.

- Para Dueños ('Owner'):
  Únicamente ven y configuran las credenciales de su propio restaurante sin
  opción a ver ni editar otros restaurantes.
